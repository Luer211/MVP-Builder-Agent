# MVP Scope

## Must Have

第一版必须包含：

- 一个 FastAPI 服务入口。
- 一个 LangGraph 正向生成流程。
- 一个明确的 `MVPilotState` 状态结构。
- 12 个文档节点或阶段输出，能覆盖目标 Markdown 文件。
- Pydantic schema 约束每个阶段输出。
- Markdown 渲染器。
- 文件系统写入器。
- 一个同步生成 API。
- 基础错误响应。
- 本地运行说明。

没有这些，核心闭环无法成立。

## Should Have

第一版可以包含，但不是必须：

- 每个 stage 的简单日志。
- 输出目录可配置。
- run id 和 manifest 文件。
- CLI 命令入口。
- 基础单元测试。
- 文档生成前的最小输入校验。

这些能力有助于开发体验，但不应该阻塞第一版闭环。

## Won't Have in MVP

第一版明确不做：

- 用户登录和权限系统。
- 数据库任务历史。
- Web 前端。
- 文档在线编辑。
- checker 自动回退机制。
- HITL 人工确认节点。
- 多模型选择。
- token 成本统计。
- 队列和异步 worker。
- 复杂观测系统。
- 自动生成项目代码。

## Scope Rationale

MVP Builder Agent 的核心价值不是“功能多”，而是“文档链路稳定、结构清晰、能被 Codex 消费”。

因此第一版要保护这些不可妥协点：

- 文档类型不能混乱。
- 阶段边界不能混乱。
- 输出结构必须稳定。
- 领域、数据、架构、API 之间必须能互相引用。
- 生成结果必须可落盘、可复现、可人工查看。

可以牺牲的是交互体验、自动化校验、历史管理和高级编排。
